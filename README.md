# JK BMS Monitor

Локальний вебзастосунок для перегляду телеметрії JK BMS через Bluetooth LE. У браузері можна підключитися до BMS, переглядати напругу та опір кожної комірки, динамічний графік напруги кожної комірки в часі, основні показники, базові прапорці стану та експортувати журнал вимірювань у CSV.

## Запуск desktop-застосунку

Для розробки потрібен Node.js 22.12 або новіший. У каталозі проєкту виконай:

```sh
npm install
npm start
```

Застосунок відкривається в окремому вікні, сам завантажує локальні файли через захищену внутрішню схему `jkbms://app` і показує власний список Bluetooth-пристроїв із пошуком, обраним і останніми підключеннями згори. Окремо запускати вебсервер або браузер не потрібно.

Щоб зібрати інсталятор macOS:

```sh
npm run dist:mac
```

Файл `.dmg` з’явиться в `release/`. Команди `npm run dist:win` та `npm run dist:linux` збирають пакети Windows і Linux відповідно на відповідних системах.

Публікація GitHub-релізу запускається пушем тегу `v*`. GitHub Actions перевіряє тести, збирає інсталятори на Windows, macOS і Linux та додає їх до релізу.
Для поширення macOS-збірки поза власним комп’ютером потрібні підписання та нотаризація застосунку.

## Запуск у браузері

Статичну версію також можна відкрити через Chrome або Edge із Web Bluetooth у безпечному контексті (`localhost` або HTTPS). Для цього запусти `python3 -m http.server 8000` і відкрий <http://localhost:8000>. Safari та Firefox не підтримують потрібний Web Bluetooth API.

## Сумісність і безпека

- Реалізація орієнтована на класичний JK02 BLE: сервіс `FFE0`, характеристика `FFE1`, запити `0x96`/`0x97` і кадри довжиною 300 байтів.
- Парсер розпізнає протоколи JK02_24S і JK02_32S окремо від фактичної кількості комірок. Наприклад, JK_B1A8S20P із 8 комірками використовує профіль JK02_32S; інші покоління JK BMS можуть мати іншу структуру кадру. Вибір профілю ґрунтується на моделі та апаратній версії з кадру пристрою.
- Опір комірок зчитується безпосередньо з поля телеметрії JK02 (роздільність 1 mΩ) і показується в картці кожної комірки; відсутнє або нульове значення позначається тире.
- Застосунок читає статус і телеметрію. Запис налаштувань навмисно вимкнений, оскільки невідомі модель BMS і відповідність команд.
- Прогноз часу до розряду рахується з залишкової ємності BMS та споживання: після 30 секунд даних використовується середній струм розряду за доступну частину останніх 5 хвилин, до того — поточний струм. Прогноз показується лише під час розряду.
- Панель «Тривоги та захист» декодує відомі біти помилок JK02_24S/JK02_32S; нерозпізнані біти показуються як код, а не приховуються.
- Графік напруги комірок має режими огляду мінімуму/середнього/максимуму, теплової карти та детального графіка однієї комірки; клік по картці комірки відкриває її детальний графік. Період можна змінювати від 1 до 30 хвилин, а щільні вимірювання агрегуються зі збереженням мінімумів і максимумів. Історія заряду/розряду групує вимірювання в періоди за напрямком струму; струм у межах ±0,1 A вважається паузою, а паузи до 5 хвилин об’єднуються. Активний час не включає паузи. Стовпчики показують енергію в kWh, а таблиця — початок і кінець періоду, активний час, SOC на початку/кінці та зміну, середню напругу й мінімальний/максимальний струм. Енергія обчислюється інтегруванням потужності в часі. Для старих записів напруга, SOC та енергія відображаються лише якщо їх можна відновити з журналу вимірювань. Позначка `≈` означає, що початок або кінець періоду не був зафіксований під час роботи застосунку. Дані зберігаються окремо для кожної BMS; додатний струм означає заряджання, від’ємний — розряджання.
- Порядок і розмір блоків дашборда можна змінювати кнопкою «Розташування»: перетягувати маркер ⠿, змінювати ширину й висоту кутовим маркером або клавіатурою. Компактна сітка заповнює вільний простір, а блоки плавно анімуються під час перестановки. Порядок і розміри зберігаються локально; «Скинути» відновлює початкове компонування. Раніше збережений порядок блоків також підтримується.
- Вимірювання зберігаються локально окремо для кожної BMS (до 2000 записів на пристрій). CSV експортується вручну; сервер або хмарне сховище не використовуються.

Перевір формат кадрів і сумісність із пристроєм перед використанням у відповідальній системі. Публічні описи протоколу: [BLE protocol notes у ESPHome JK-BMS](https://github.com/syssi/esphome-jk-bms/blob/main/docs/protocol-design-ble.md) та [Better BMS App](https://github.com/encap/better-bms-app).
